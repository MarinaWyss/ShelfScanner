## Suggested change

**Tell the choosing prompt how many picks to return when the verified list
is short.** Affects `docs/specs/recommendation.md` (prompt and checks).

- *What is wrong.* `recommend_v6` says "exactly five" twice and "fewer
  than five, recommend all" once. Since the catalogue check (007) drops
  titles before choosing, short lists reach the model more often than they
  did when the prompt was written, and the code expects
  `min(5, len(list))`.
- *How the rows show it.* Four app rows (174, 175, 238, 239) on two days
  failed with five picks from a list of three or four, and the reader got
  an error each time. Recommendation 294 shows the softer form: four
  stretched picks whose own reasons say they do not fit.
- *What to change.* A `recommend_v7` that states the number, built from
  the list the model sees ("recommend exactly N books", N =
  `min(5, len(list))`), drops the fixed "five" from the last line, and
  lets a pick that fits weakly say so, not argue it fits. Add one
  short-list photo from rows 174/175 or 238/239 and recommendation 294's
  photo to the test set with labels first, so the change has a case to
  pass.
- *How we would know.* The new test-set photos return the right count on
  every model in the stage tables; `research.check` shows no regression on
  validity, overlap, latency or cost against the baseline; and the next two
  reviews show no `expected N recommendations` rows.

A smaller one, affecting `docs/specs/monitoring.md`: group model-failure
kinds with the numbers taken out, so `expected 3` and `expected 4` count as
one kind. The four rows above missed the Patterns list only because the
number split them.

To watch, not change: Gemini truncations at 8,192 tokens (three rows this
