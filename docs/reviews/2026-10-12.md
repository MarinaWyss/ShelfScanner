## Suggested change

**Choosing: ask for the number of picks the shelf allows, not five.**

- *What is wrong.* `prompts/recommend_v6.md` says "Recommend exactly five
  books" and "check each of your five titles", and only then "If the list
  has fewer than five books, recommend all of them". `recommend.py` expects
  `min(5, titles)` picks, but nothing in the request tells the model that
  number, and the schema (`RECOMMENDATIONS_SCHEMA`) has no `maxItems`.
- *How the rows show it.* Four choosing rows on two days (174, 175, 238,
  239) returned five picks from three- and four-title lists and failed the
  count. Recommendation 294 returned five picks whose reasons hedge on four
  of them, and the reader marked all four "not for me": the same instruction
  forcing picks the shelf did not have.
- *What to change.* A new prompt version that states the count once and
  conditionally ("recommend up to five; fewer if fewer fit, never more than
  the list"), the count passed in the input text, and `maxItems` set per
  call. Whether a pick may be dropped for poor fit (fewer than `min(5,
  titles)`) is a behaviour change to `docs/specs/recommendation.md`, so the
  proposal should decide it explicitly; the wrong-count check moves with it.
- *How we would know.* The two short-shelf photos from this review join the
  test set; `research.check` passes on the core set with the new prompt;
  the next reviews show no `expected N recommendations` rows; and the
  not-for-me rate per pick on scans with fewer than five matching books
  falls (save rate per scan, the primary metric, should not).

Affects `docs/specs/recommendation.md` and `docs/specs/feedback.md` (the
not-for-me denominator if picks can be fewer). A proposal in `docs/changes/`
and Marina's yes come first.
